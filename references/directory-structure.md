# 项目任务目录结构规范

适用范围：`<DBCODEBOOK_HOME>\演示` 下所有定义、宣传、封面、小红书、工具试验和后续同类任务。

本规范解决一个核心问题：正式产物目录只放正式交付物；过程材料、执行记录、测试产物、临时草稿和归档材料必须进入对应过程层或归档层，不能混进正式产物层。

## 1. 四层目录

### 正式产物层

正式产物层只保存最终可交付、可被用户直接使用或被后续流程读取的成果。

示例：

- `<DBCODEBOOK_HOME>\演示\定义\CHARLS\001_吸烟状态\`
- `<DBCODEBOOK_HOME>\演示\宣传\公众号\CHARLS\001_吸烟状态\`

允许内容：

- 主题正式成果文件，例如 xlsx、HTML、正式笔记、正式 SVG、正式 PNG、正式封面。
- 主题目录本身，例如 `001_吸烟状态`、`002_饮酒状态`。

禁止内容：

- 过程卡、执行记录、回传包、验收报告。
- 临时截图、调试 HTML、测试 SVG、contact sheet、草稿图。
- 工具自检 JSON、临时 QA、试验脚本输出。
- `archived_`、`superseded_`、`draft_`、`test_` 等过程或历史材料。
- 单独放在数据库根目录的过程说明，例如 `<DBCODEBOOK_HOME>\演示\宣传\公众号\CHARLS\过程卡_xxx.md`。

### 过程执行层

过程执行层保存执行过程、过程卡、回传材料、工具自检结果、临时 QA、任务草稿和本轮可追溯记录。

示例：

- `<DBCODEBOOK_HOME>\演示\定义\_执行线程\CHARLS\001_吸烟状态\`
- `<DBCODEBOOK_HOME>\演示\宣传\公众号\_执行线程\CHARLS\封面\process_cards\`
- `<DBCODEBOOK_HOME>\演示\宣传\小红书\_执行线程\CHARLS\007_城乡\`

要求：

- 所有过程卡必须落在 `_执行线程` 下。
- 执行线程产生的检查结果、过程截图、旧日志归档、临时说明必须落在 `_执行线程` 下。
- 大脑线程如被明确授权直接执行并需要落盘，也必须写入 `_执行线程\_大脑临时\...` 或对应主题过程目录。

### 模板工具层

模板工具层保存可复用模板、公共生成器、公共参数、规范和工具脚本。

定义模块的正式规则源：

- `<SKILL_ROOT>\references\`
- `<SKILL_ROOT>\assets\`
- `<SKILL_ROOT>\scripts\`

宣传模块由各渠道自己的 Skill、模板和工具管理，例如：

- `<DBCODEBOOK_HOME>\演示\宣传\公众号\_模板\`
- `<DBCODEBOOK_HOME>\演示\宣传\公众号\_工具\`
- `<DBCODEBOOK_HOME>\演示\宣传\小红书\_模板\`
- `<DBCODEBOOK_HOME>\演示\宣传\小红书\_工具\`
- `<DBCODEBOOK_HOME>\演示\宣传\_公共\`

要求：

- 通用规则写在模板/流程/规范文件中，不写在主题正式目录。
- 生成器如需写过程卡，默认写入 `_执行线程`，不得写入正式产物层。
- 生成器不得把调试产物写到当前临时工作区。

### 归档层

归档层保存已经被替代、仅作历史参考的材料。

示例：

- `<DBCODEBOOK_HOME>\演示\定义\_执行线程\CHARLS\_归档\`
- `<DBCODEBOOK_HOME>\演示\宣传\公众号\_归档\`
- `<DBCODEBOOK_HOME>\演示\宣传\小红书\_归档\`
- 主题过程目录下的 `archived_logs`、`archived_nonstandard_files`

要求：

- 被替代但仍可能需要追溯的材料放归档层。
- 归档材料命名应带原因或状态，例如 `superseded_...`、`archived_...`。
- 不再被使用且无追溯价值的临时材料可以直接删除。

## 2. 落盘规则

### 默认禁止写临时工作区

除非用户明确指定，任何任务不得把过程材料写到：

- `<USERPROFILE>\Documents\Codex\...`
- `<USERPROFILE>\AppData\Local\Temp\...`

允许例外：

- 浏览器、系统或 Codex 自动产生的临时缓存。
- 用户剪贴板截图。
- 一次性只读检查无需落盘。

如果必须生成临时文件，应写入已配置的项目过程目录，并在任务完成后清理或归档。

### 正式产物与过程材料必须分离

执行任务时先判断文件性质：

| 文件性质 | 应放位置 |
| --- | --- |
| 用户最终使用的正式成果 | 对应正式主题目录 |
| 过程卡 / 回传包 / 执行记录 | `_执行线程` |
| 自检 JSON / 临时 QA / 调试截图 | `_执行线程` |
| 定义公共规则 / 生成器 / 参数 / 模板 | 本 Skill 的 `references`、`scripts` 或 `assets` |
| 宣传公共生成器 / 参数 / 模板 | 对应宣传渠道的 Skill、`_模板` 或 `_工具` |
| 旧规则 / 旧产物 / 被替代试验 | `_归档` 或过程目录归档子目录 |
| 无追溯价值临时文件 | 删除 |

## 3. 任务开始前检查

每个执行线程开工前必须确认：

- 正式目录路径。
- 过程目录路径。
- 模板/规则源路径。
- 本轮会新增或修改哪些正式产物。
- 本轮会新增哪些过程材料，过程材料放在哪里。

如果任务包没有指定过程目录，执行线程必须自行使用对应模块的 `_执行线程` 目录，不得把过程卡写到正式目录。

## 4. 任务完成后检查

每个执行线程回传前必须检查：

- 正式产物层是否只包含正式交付物和主题目录。
- 是否误把过程卡、测试文件、自检 JSON、临时截图放进正式目录。
- 过程材料是否进入 `_执行线程` 或归档层。
- 如果发现正式目录有过程材料，必须先移动到过程层或归档层，再回传。

## 5. 大脑线程职责

大脑线程负责维护目录结构边界：

- 派发任务时明确正式目录和过程目录。
- 判断是否需要归档或删除混杂材料。
- 发现正式层混入过程材料时，优先从规则/生成器源头修正，不只移动单个文件。
- 不把个案修复当作完成，必须检查同类任务是否存在相同写入路径。

## 6. 当前模块约定

### 定义模块

- 正式成果：`<DBCODEBOOK_HOME>\演示\定义\CHARLS\00X_主题\`
- 执行过程：`<DBCODEBOOK_HOME>\演示\定义\_执行线程\CHARLS\00X_主题\`
- 流程规则：`<SKILL_ROOT>\references\`
- 模板：`<SKILL_ROOT>\assets\`
- 工具：`<SKILL_ROOT>\scripts\`
- 索引：`<DBCODEBOOK_HOME>\演示\定义\_索引\`

### 宣传模块

宣传模块必须显式区分渠道，禁止再把宣传根目录默认解释为公众号。

```text
宣传\
├─ _公共\
├─ 公众号\
└─ 小红书\
```

公众号：

- 正式成果：`<DBCODEBOOK_HOME>\演示\宣传\公众号\<DATABASE>\00X_主题\`
- 执行过程：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_执行线程\<DATABASE>\...`
- Skills：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_skills\`
- 模板：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_模板\`
- 工具：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_工具\`
- 索引：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_索引\`
- 归档：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_归档\`
- 样式试片：`<DBCODEBOOK_HOME>\演示\宣传\公众号\_样式试片\`

小红书：

- 正式成果：`<DBCODEBOOK_HOME>\演示\宣传\小红书\<DATABASE>\00X_主题\`
- 执行过程：`<DBCODEBOOK_HOME>\演示\宣传\小红书\_执行线程\<DATABASE>\...`
- Skills：`<DBCODEBOOK_HOME>\演示\宣传\小红书\_skills\`
- 模板：`<DBCODEBOOK_HOME>\演示\宣传\小红书\_模板\`
- 工具：`<DBCODEBOOK_HOME>\演示\宣传\小红书\_工具\`
- 索引：`<DBCODEBOOK_HOME>\演示\宣传\小红书\_索引\`
- 归档：`<DBCODEBOOK_HOME>\演示\宣传\小红书\_归档\`

跨渠道公共层：

- 只有同时服务公众号和小红书的 Skill、模板、工具和规则才进入 `<DBCODEBOOK_HOME>\演示\宣传\_公共\`。
- 渠道专属能力必须放入最低可用范围，不能为了“看起来公共”而放在根级。
- 公众号富文本与封面属于公众号渠道；小红书页面生成器属于小红书渠道。
- 历史过程记录可保留旧路径原文，但新任务不得继续写入旧根级 `宣传\CHARLS`、`宣传\ELSA`、`宣传\_工具`、`宣传\_模板` 或 `宣传\_执行线程`。

## 7. 典型错误和处理

- 错误：在 `<DBCODEBOOK_HOME>\演示\宣传\公众号\CHARLS\` 根目录放 `过程卡_xxx.md`。
  - 处理：移动到 `<DBCODEBOOK_HOME>\演示\宣传\公众号\_执行线程\CHARLS\...\process_cards\`，并修正生成器写入路径。
- 错误：在正式主题目录放工具自检 JSON。
  - 处理：移动到对应过程目录；若是脚本生成，修正脚本输出路径。
- 错误：在 Codex 临时 workspace 生成测试产物。
  - 处理：清理临时产物；后续任务把临时产物写入已配置的项目过程目录。
- 错误：把旧试验目录当作新规则源。
  - 处理：移动到归档层，并在模板/规则文件中引用正式规则源。
